# `looks_like` detector

The detector behind `hide: - email: { looks_like: [password_reset, login_code] }`
(spec: Hiding, `looks_like`). D10a ships it as a standalone module with its
evaluation gate. D10b wires it into the hide path; nothing here reads rules,
touches the schema or filters responses.

## Contract for D10b

```ts
import { classifyLooksLike } from "../core/lookslike/classify.ts";
import { loadLooksLikeModel } from "../lookslike/load.ts";

// Once, at boot. Never throws: a missing, corrupt or stale weights file is
// `{ status: "unavailable", path, error }`, and heel keeps serving.
const loaded = loadLooksLikeModel();
const model = loaded.status === "loaded" ? loaded.model : undefined;

// Per message, per hide entry. Pure and synchronous; never throws.
const result = classifyLooksLike(message, entry.looks_like, {
  model,
  now: () => performance.now(),
});
const hide = result.verdict !== "no_match";
```

**Hide on `match` and on `uncertain`.** `no_match` is the only verdict that
lets a message through, and it comes only from a loaded model scoring a
readable message below its threshold within the time budget (I-44).
`uncertain` is kept separate from `match` so the hide path can count
fail-closed outcomes in a metric, as the Fail-closed table requires.

**What the caller supplies** (`LooksLikeMessage`):

| Field        | What to pass                                                                                     |
| ------------ | ------------------------------------------------------------------------------------------------ |
| `subject`    | The decoded Subject header.                                                                      |
| `from`       | The From header as received, `Name <addr>` or a bare address.                                    |
| `body`       | The text/plain part, or the text/html part when there is none. The detector reads the first 4,096 characters of text. |
| `bodyFormat` | `"text"` or `"html"`, matching `body`.                                                           |
| `unreadable` | Set when MIME parsing found no readable body: S/MIME or PGP/MIME, or a part that would not decode. |

The detector flags inline PGP and image-only HTML itself. Each message is
judged on its own, so a reply that quotes a hidden message is hidden only if
it matches too (README "Hiding").

**What comes back.** `result.categories[c]` holds a verdict and a reason for
each requested category:

| `reason.kind`       | Verdict                          | Meaning                                                    |
| ------------------- | -------------------------------- | ---------------------------------------------------------- |
| `pattern`           | `match`                          | A recall pattern hit; `pattern` names it.                  |
| `classifier`        | any                              | The model's probability, `score`.                          |
| `unreadable`        | `uncertain`                      | Encrypted, image-only or unparseable, with no pattern hit. |
| `model_unavailable` | `uncertain`                      | No model loaded.                                           |
| `timeout`           | `uncertain`                      | Classification ran past `budgetMs` (default 200 ms).       |
| `error`             | `uncertain`                      | Something threw; `error` is the error's name, never its message. |

Reasons never carry message content, so they are safe for audit rows and
logs. Pattern hits stand even past the budget, because the patterns ran first.

**D10b owns:** the `looks_like` key in the rules schema, calling this from the
hide filter, the per-`(account, messageId, hide-rules hash)` verdict cache, the
I-44 metric, and the I-43 property that `looks_like` only ever adds to the
hidden set.

## How it decides

For each requested category, in order:

1. **Patterns**, tuned for recall (`patterns.ts`): reset and code keyword
   phrases, a code-shaped token near a keyword, URL heuristics, and WICG
   `@origin #code` lines. Text is NFKC-normalized and stripped of
   default-ignorable characters first, so zero-width and full-width evasions
   don't slip past.
2. **Unreadable bodies** are `uncertain`.
3. **The linear classifier** (`features.ts`, `model.ts`): hashed word and
   character n-grams over subject, body, sender and URLs, with one
   logistic-regression head per category. A score at or above `matchAt` is
   `match`, below `noMatchBelow` is `no_match`, and in between is
   `uncertain`.

## Weights, corpus and the gate

- `src/lookslike/weights.json` is generated by `pnpm gen:looks-like`.
  Regenerate it; don't edit it. It records the SHA-256 of the corpus manifest
  it was trained against, and `pnpm eval:looks-like` refuses to measure
  weights that don't match.
- `corpus/looks-like/manifest.json` lists every source with its pinned
  commit, license and paths, plus the held-out split and digests. Synthetic
  reset and code mail is rendered from permissively licensed auth-template
  sources. Ordinary mail comes from the CMU Enron release, which states no
  license. The repo commits only archive paths and content hashes
  (`enron-*.tsv`), never message text. The scripts read the archive from
  `.cache/looks-like/` or `--archive`, and verify its pinned SHA-256 first.
- **The gate** (spec D10 row): on the held-out split, recall must be at least
  0.99 per category, and the false-positive rate on ordinary mail at most 5%.
  It also needs at least 100 positives per category and 1,000 ordinary
  messages, so it can't pass on an empty set. CI runs it as a blocking job.

The held-out split is by source: held-out synthetic mail comes from template
sources the model never trained on, and held-out ordinary mail from Enron
mailboxes outside the training split.

### Known limits

- **Transactional mail that quotes a code is often hidden.** The synthetic
  hard negatives (meeting passcodes, flight confirmation codes and
  account-security notices) are reported but not gated, and most of them are
  hidden. Enron is 2001 corporate mail with little automated mail, so the
  ordinary false-positive rate understates this. Watch mode on a real inbox
  is the check (spec: load-bearing assumption).
- **The patterns were written after reading every template source,** held-out
  ones included. Held-out recall therefore measures the classifier on unseen
  sources, not the patterns.
